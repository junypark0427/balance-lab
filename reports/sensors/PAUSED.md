## 현재까지 실제 확인

- 현재 USB에 연결한 두 보드는 ESP32-D0WD-V3 rev 3.1입니다.
- 두 장치의 기존 성공 펌웨어를 리셋해 GPIO21/22, WHO_AM_I=0x68 및 가속도 출력을 확인했습니다.
- 첫 버전 게임용 펌웨어는 두 기기에 각각 업로드했고 해시 검증을 통과했습니다.
- Python에서 서로 다른 MAC ID의 Roll/Pitch/가속도/자이로를 동시에 수신했습니다.
- 역할: P1=esp32-680947606060, P2=esp32-08d1f9e7279c. 로컬 설정에 저장되어 있습니다.
- 첫 두 기기 모두 Pitch 설정은 실제 손목 방향과 맞지 않았습니다. 사용자의 구체적 손등/손바닥
  굽힘 재검사 뒤 현재 P1=Pitch, P2=Roll로 수정했습니다. 최종 방향/반전 확인은 미완료입니다.
- 사용자 중립 자세에서 양쪽 READY 및 0 입력 보정을 확인했습니다. 이후 자세 변경으로 새 보정이 필요합니다.
- 실제 LEVEL 01 센서 플레이에서 두 축 동시 입력, ±15도 제한, 실제 공의 이동을 기록했습니다.
- live_game.csv의 seconds=315.0667에 실제 Goal/Mission Success를 관찰했습니다.
  그 행은 센서 모드, keyboard event count=0입니다. 공 좌표/속도 직접 수정 없이 도달했습니다.
  다만 최종 축 교정 전의 주행이므로 최종 조작감 검증 완료로 간주하지 않습니다.
- 합성 UDP + 실제 Godot 4개 Scene 검사 35개 통과, Python 검사 최종 11개 통과,
  기존 공 물리/UI 회귀 검사는 실패 없음. 실제 사람의 LEVEL 02~04 플레이는 아직 하지 않았습니다.

## 중단 직전 발견·수정 중인 사항

- P1 측정이 오래되지 않은 시점까지 정상이다가 중단된 상태를 발견했습니다.
  두 보드를 직접 열어 HELLO 이후 START를 보내자 각각 약 190개 정상 프레임을 다시 받았습니다.
  실제 중단의 원인을 단정하지 않습니다.
- 코드 검토에서 기존 순번 복구가 부팅 후 3초 이내에 한정되는 약점을 발견했습니다.
  소스에 부팅별 boot ID를 추가하고 브리지가 이를 통해 순번을 리셋하도록 개선했습니다.
  3초 이후 재시작 복구 회귀 검사를 포함한 Python 검사 11개가 통과했습니다.
- 펌웨어의 자이로 편향 수집도 정지 조건을 만족할 때만 진행하도록 보강했습니다.
- **이 마지막 보강 펌웨어는 아직 두 보드에 업로드하지 않았습니다.**
  현재 보드에는 첫 버전 게임용 펌웨어가 있고, 디스크에는 보강 소스가 있습니다.
- Python 브리지는 종료했습니다. 중단 요청에 따라 제가 연 실제 테스트 게임도 종료했습니다.
  Arduino IDE와 사용자의 다른 앱은 종료하지 않았습니다.

## 재개 순서

1. 최신 소스 컴파일 결과 확인 → 두 보드에 한 대씩 115200으로 업로드/검증.
2. hardware/start_sensors.command 실행, 두 ID/역할 복구 및 정상 수신 확인.
3. 현재 손목 장착 방향으로 P1 좌우/P2 손등·손바닥 굽힘을 각각 검증하고 필요한 반전 설정.
4. 사용자가 준비한 중립 자세에서 다시 보정. 완료 시 즉시 손목 유지 종료 안내.
5. LEVEL 01을 새로 시작해 교정된 두 센서 동시 조작/복귀/키보드 확인.
6. 실제 USB 한 개 해제·재연결과 데이터 중단 안전성, LEVEL 02~04 실제 USB 입력 확인.
7. 운영 문서/validation.md를 최종 결과로 갱신. Windows EXE와 Git 작업은 별도 요청 전 금지.
