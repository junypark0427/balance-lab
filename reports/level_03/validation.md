## 플레이 검증의 구분

### 연속 경로: 실제 물리 자동 플레이

Godot 게임 엔진을 실제 실행하고 동일한 RigidBody3D, 모든 실제 충돌체, 플랫폼 제어기를 사용했습니다.
경로 탐색은 조작할 목표점만 정합니다. 탐색 결과만으로 성공을 판정하지 않습니다.
탐색 후 매 물리 프레임 공의 오차/속도를 읽어 입력을 주고, Goal의 실제 body_entered가 발생해야 성공입니다.
이 연속 이동 중에는 공의 좌표/선속도/각속도 쓰기, 순간이동, 충돌 비활성화, 강제 힘을 사용하지 않습니다.

- 아날로그 입력 어댑터 실행: 약 **166.6초**, 추가 낙하 없이 실제 Goal 도달.
- 네 키 이벤트 실행: 약 **169.1초**, 추가 낙하 없이 실제 Goal 도달.
  InputEventKey 물리 키 A/D/↑/↓ → InputMap → 기존 TiltInput → 기존 플랫폼 제어기로 전달합니다.
  센서 입력 모드는 꺼져 있습니다. 목표 기울기를 조절하도록 키를 눌렀다 놓는 자동 조작입니다.
- 첫 벽 구간 통과, 실제 대각선 벽 및 피라미드 접촉, 필수 통과구 아래 통과, 마지막 Goal 도달을 기록했습니다.
- Goal 이후 공 고정, 플랫폼 조작 정지, 타이머 정지 및 기존 Mission Success 결과 UI를 확인했습니다.
- 초기 단순 디지털 조작기는 첫 코너에서 과조작하여 시간 제한에 걸렸습니다.
  게임 형상/충돌을 바꾸지 않고 테스트 조작기를 현재 기울기에 맞춘 키 눌림/해제 방식으로 고쳤습니다.
- 이 자동 플레이의 시간은 사람의 예상 클리어 시간이나 난이도를 보장하지 않습니다.

### 독립 접촉 실험

연속 클리어와 별도 실험입니다. 각 실험 **시작 시** 공을 장애물 옆/위에 배치하며,
충돌 실험 일부는 초기 속도를 줍니다. 따라서 이 결과로 시작점에서 모든 장애물 정상에 올라갔다고 주장하지 않습니다.

- 주황색 두 기둥: 실제 곡면 측면 접촉, 반발/방향 전환, 바닥 근처 유지.
- 보라색 돔: 실제 경사면 접촉 후 회전하며 아래로 이동. 끼임 없음.
- 피라미드 7개 전부: 실제 삼각 경사면 접촉 후 회전/하강. 비정상 정지 없음.
- 직선 벽과 대각선 벽: 초기 25m/s 충돌에서 CCD가 관통을 방지하고 반발 발생.
- 통과구 아래 구체 스윕 통과, 위쪽 상단 보는 충돌 유지.
- 양축 ±15°, 모든 충돌체 동반 회전, 낙하/회전 초기화, 카메라 복귀와 범위 제한.

### 실제 GUI / 사람 조작 범위

실제 Metal 게임 창에서 A, ↑, F3를 OS 입력 도구로 전달했습니다.
진단 Events=6, A에서 P1=-1, ↑에서 P2=-1, 정확한 InputMap 매칭을 확인했습니다.
도구의 짧은 키 탭 전달 검사이며 **사람이 키를 길게 누르며 처음부터 끝까지 클리어한 결과는 아닙니다**.
별도로 실제 렌더링 창에서 자동 물리 플레이와 성공 화면을 검증했습니다.

UI 테스트는 실제 UI 버튼 이벤트로 LEVEL SELECT, 일시정지, 재시작, Retry, Lobby를 검사합니다.
이 테스트의 결과창 분기는 공을 Goal에 배치하는 독립 UI fixture입니다. 연속 클리어 증거와 혼동하지 않습니다.

